# Obseil sample datasets

Purpose-built fixtures. Each file isolates one behaviour of the analysis
pipeline so that a test can assert both that the right detector fires **and**
that the others stay quiet — a detector that flags everything is as useless as
one that flags nothing.

All files are generated by [`data/generate_samples.py`](../generate_samples.py)
from a fixed seed (`20260831`), so they can be regenerated byte-identically:

```bash
python data/generate_samples.py
```

They describe a synthetic card-transaction table. No real or personal data is
involved.

## Shared schema

| Column | Type | Notes |
| --- | --- | --- |
| `transaction_id` | text | Candidate identifier, unique in every file except `duplicate_records` |
| `customer_id` | text | High-cardinality categorical |
| `transaction_date` | date (ISO) | Parsed as datetime by type inference |
| `amount` | float | Log-normal — realistically long right tail |
| `items` | integer | Small positive count |
| `merchant_category` | text | 7 categories |
| `channel` | text | 3 categories |
| `country` | text | 6 categories |
| `customer_age` | integer | 18–81 |
| `loyalty_points` | integer | 0–5000 |

## The files

### `clean_transactions.csv` — 600 rows
**Designed to test:** the absence of false positives.

No missing values, no duplicates, no constant columns, and the `amount` tail is
clipped at the 99th percentile so even the IQR rule has nothing legitimate to
flag. **Zero rule findings** here is the baseline against which every other file
is judged, and the test suite asserts it.

The unsupervised model may still surface a handful of candidates (~1% of rows).
That is an expected property of anomaly detection on any real dataset, not a
defect: it is reported in a separate category and barely moves the score.

### `clean_transactions.xlsx` — 600 rows
**Designed to test:** the Excel reader.

The same data as above in a single worksheet named `transactions`. Profiling it
must produce the same schema and statistics as the CSV.

### `missing_values.csv` — 500 rows, 11 columns
**Designed to test:** missing-value detection and severity banding.

Four columns with deliberately different missingness rates, one per severity
band:

| Column | Missing | Expected severity |
| --- | --- | --- |
| `country` | ~4% | Low |
| `customer_age` | ~18% | Medium |
| `loyalty_points` | ~45% | High |
| `promo_code` | ~92% | Critical |

Plus 12 rows in which eight of eleven fields are blank, for the row-level
missingness check. Those rows are individually valid-looking in any single
column, which is the point.

### `duplicate_records.csv` — 440 rows
**Designed to test:** duplicate detection, in its two distinct forms.

* **40 exactly duplicated rows** — double counting.
* **25 rows sharing `TXN-000001`** — a broken key in a column that is otherwise
  a candidate identifier.

The rows are shuffled, so detection cannot rely on duplicates being adjacent.

### `outliers.csv` — 500 rows
**Designed to test:** univariate statistical outlier detection.

* 15 `amount` values between 45,000 and 120,000 against a body clustered around
  20–90.
* 8 impossible `customer_age` values (0, 1, 199, 240).

Both are visible by looking at a single column — which is exactly what
distinguishes them from `anomalous_transactions.csv`. The engine finds
**exactly 15 and exactly 8**, which the test suite asserts.

### `invalid_values.csv` — 450 rows, 11 columns
**Designed to test:** validity rules, as opposed to distribution rules.

* 18 negative `amount` values and 9 negative `items` — negative where only
  positives are possible.
* 14 unparseable or impossible `transaction_date` values
  (`not-a-date`, `2026-13-45`, `31/02/2026`, empty).
* 11 empty or whitespace-only `merchant_category` values, which pandas does
  **not** read as missing — they hide in a column that looks complete.
* 6 text values (`unknown`, `n/a `) in the otherwise-numeric `loyalty_points`,
  making it a numbers-stored-as-text column.
* `batch_version`, constant at `v3` — a column carrying zero information.

### `anomalous_transactions.csv` - 700 rows
**Designed to test:** the machine-learning component, and only that.

Unlike the other fixtures, the *normal* data here has deliberate structure:
`amount` is driven by the basket size (`items` x a unit price), and
`loyalty_points` accumulate with `customer_age`. Twelve rows then violate that
structure while keeping every individual value inside its own column's ordinary
range:

* a basket of **one item priced like a basket of ten**
* an **18-year-old with a maximal loyalty balance**

Every marginal distribution is untouched, so **no per-column rule fires** - the
entire deterministic engine reports zero findings on this file. What is unusual
is the *combination*, which places these rows in a sparsely populated region of
the joint distribution.

This is the fixture that justifies having an ML component at all, and the test
suite asserts that the Isolation Forest finds **all twelve**.
